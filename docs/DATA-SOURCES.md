# 数据来源、可信度与合规边界

这一页说明「地图上的价格是怎么来的」，以及**哪些做法本项目明确不做**。改采集脚本或导入逻辑前请先读这一页。

## 核心原则

> 采集只用于**发现**，公开只来自**核验**。

- 采集脚本的输出永远是「线索」，写进 `source_leads`，**不会**直接进入公开地图。
- 公开的每条价格都必须带：来源、核验方式、核验日期。
- 抽不到的信息写「待补」占位并标记，**绝不臆造**——没有坐标不进公开。

## 可信度分级

| 级别 | 依据 | 是否计入「已核验」 |
|---|---|---|
| 高可信 | 现场菜单、价签、当次消费小票 | ✅ |
| 中高可信 | 商户官方菜单，或两名独立用户确认 | ✅ |
| 需留意日期 | 价格仍有效，但优先看核验日期 | ✅ |
| 低可信 / 未核验 | 社区内容、创作者内容、外部线索 | ❌ 只作线索展示 |

`placeTrust` 只把非「低可信」的餐食计入已核验数。数据库层面还有一道硬约束：`price_reports` 上的触发器**禁止** `external_lead` 来源变为 `verified`——即社区/创作者内容永远无法被标成已核验。

## 公开资格

一条价格能出现在公开地图上，需要同时满足（实现见 `lib/server/public.ts`、`lib/server/repository.ts`）：

1. 门店 `active` 且营业中；
2. 存在 `active` 餐食，且有 **180 天**内的价格；
3. 该门店至少有**一份 ≤ ¥15 的单人餐食**（店级门槛）；
4. `city` 在公开白名单内（北京 / 上海 / 广州 / 深圳 / 杭州）。

高于 15 元的餐食**如实展示**，但展示价 sanity 上限 ¥200。超过 180 天的价格会从地图隐去，直到有人重新确认。

## 来源类型

| 来源 | 入口 | 说明 |
|---|---|---|
| 人工核验 | 后台录入 / CSV 导入 | 主路径。现场看到的菜单、价签、小票 |
| 用户匿名投稿 | `/submit` | 新地点 / 价格变化 / 纠错 / 停业四类；需人工审核后才可能公开 |
| 创作者内容 | `npm run collect:creators` → `/admin/creator-import` | B站 / YouTube 公开元数据；**只存元数据与外链** |
| 搜索引擎 + LLM | `npm run collect:web` → `/admin/creator-import` | 搜索引擎广撒网，LLM 抽取店名/地址/菜品/价格 |
| CSV 批量 | `/admin/import` | 两阶段：预览 → 人工确认坐标 → 全有或全无提交 |

### 创作者内容聚合（B站 / YouTube）

- B站走公开 `search/type` 接口做关键词检索，匿名请求会遇 `-412` 限流（脚本已线性退避重试；可用 `BILIBILI_COOKIE` 缓解）。
- YouTube 走公开频道 RSS（默认关闭），视频的实际归属仍需**人工确认**（存在官方同步与第三方搬运）。
- 展示时标「未核验 · 创作者来源」、来源格式 `平台@UP主`，并链接回原内容。
- **不下载、不镜像**视频或封面，只保存标题、链接、发布时间、播放量等元数据。

### 搜索引擎采集（可选）

- `scripts/web-collect.ts`：默认百度（必应在本机实测被反爬拦截），解析跳转取最终 URL；正文启发式抽取；LLM 抽取店名/地址/菜品/价格；按店级 ≤15 元过滤。
- 需要自备 LLM Key（默认 MiniMax 的 OpenAI 兼容接口）。
- 已知限制：攻略/盘点类文章抽不出店名（预期）；百度自有站点会被 `blocked_host` 拦掉；LLM 抽出的价格可能 >15 元或缺地址，需要人工补。

## 明确不做的采集

以下平台**不要**接入自动化抓取，PR 提了也会被拒：

| 平台 | 原因 |
|---|---|
| 小红书 | 实测被风控拦截（IP 风险），且违反其服务条款 |
| 抖音 | 实测需要过验证码 |
| 大众点评 | 实测反爬 |

想收录这些平台的内容，只能走**人工录入或用户投稿**。

其他红线：

- 不绕过 `robots.txt`，不伪造登录态、不调用需要付费/授权的私有接口。
- 不抓取个人隐私信息（真实姓名、手机号、住址、身份证件、精确轨迹）。
- 不搬运、不镜像他人视频、封面或文章全文。
- 不把创作者/社区内容标为已核验。

## 隐私与数据最小化

- **匿名投稿**：不收集姓名、手机号等实名信息；成功页只显示一次随机查询码，查询码只用于查状态。
- 查询码与来源指纹都只存**不可逆哈希**（按每日轮换盐 + 服务端密钥）。
- **图片**：服务端用 Sharp 重新编码为 WebP 并去除元数据（含 GPS）；证据图默认 `admin_only`，公开前必须完成权利确认 + 人工隐私复核 + 关联正式价格事实。
- 公开 DTO 不包含 `source_url`、审核备注、审计记录、原始 payload、文件路径。
- 若你的部署把数据放在境外服务器，请在页面上（或关于页）给出最小隐私声明：说明餐食图片与位置信息存放地点、仅用于展示平价餐食信息、投稿默认仅管理员可见、公开前经人工审核、图片已去除元数据。数据出境相关的合规责任由部署者承担。

## 贡献数据的方式

本项目**不接受**未经核验的批量数据 PR。想贡献数据请：

1. 在你自己的部署实例上用 `/submit` 投稿；或
2. 在后台 `/admin/creator-import` 逐条人工确认后导入。

想贡献**城市目录**（行政区 / 商圈），请在 PR 里附上官方或可公开核实的边界来源（坐标一律 GCJ-02）。
