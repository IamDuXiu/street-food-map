## 2026-09-02 · 阶段 1 数据边界与安全写入

页面和 API 通过 repository/service 使用 better-sqlite3，不在页面中拼接业务写 SQL。SQLite 启用 WAL、foreign_keys 和 busy_timeout；迁移按文件版本执行，金额统一以分、时间统一存 UTC。公开 DTO 只输出地点、餐食、价格和可信状态，不输出来源链接、后台备注、审计摘要或投稿原始 payload。

管理员会话使用 scrypt 密码哈希、签名 HttpOnly Cookie、8 小时过期和 password_version 失效机制；失败来源 15 分钟内累计 5 次锁定。所有后台写请求同时检查 Origin 和双提交 CSRF。CSV 先服务端预览，模板、坐标、日期、价格和来源链接全部通过后，才在单事务中提交；同一批次的多条餐食按地点键归并，已存在的疑似重复地点则必须先处理。阶段 1 明确拒绝非空 `evidence_filename`，避免仅写数据库而没有安全文件的悬挂引用，图片导入留到阶段 3。合并地点保留餐食价格历史、标签并集和审计记录，重复地点标记 merged 而不物理删除。

浏览器与服务端共用 RFC 4180 CSV 解析器，避免中文地址中的逗号、引号或换行在前端预览时被破坏；同一来源链接可用于同一地点的多份餐食，但不能跨地点复用。公开 DTO 在最终出口再次执行 25 元和 180 天双重门槛，避免旧价格绕过查询层进入页面。

## 2026-09-02 · 备份和维护的保护性操作

备份先做 WAL checkpoint，再生成 SQLite 快照、关键表 JSON、uploads 和 SHA-256 manifest。恢复先安全检查 ZIP 条目、manifest 全量文件、schema、SQLite integrity_check 和媒体引用，再自动备份当前库；只有明确确认词才同时替换 DB 与 uploads，任一步失败均回滚两者。维护任务先移动待清理文件，数据库事务成功后才删除；文件失败会回滚移动并保留原 submission type 与 payload，只添加 `payload_cleared` 标记。

## 2026-09-02 · 后台页面先鉴权

所有使用 `AdminShell` 的服务端页面在读取 SQLite 前调用统一 page guard；匿名访问 `/admin` 及其子页面重定向 `/admin/login`。测试与 e2e 使用显式 `DEMO_AUTH=1`、强随机会话密钥和单 worker，避免演示 SQLite 并发写入互相污染；生产模式不允许 demo fallback。

## 2026-09-02 · 测试与证据导入边界

Vitest 在模块导入前设置唯一临时 `DATABASE_PATH`、`UPLOADS_DIR` 和 `BACKUPS_DIR`；Playwright 通过固定的 `/tmp/shenzhen-budget-map-playwright` 目录启动隔离服务。默认演示库只由产品负责人显式运行 setup/backup 维护。阶段 1 CSV 只接受地点、餐食、价格与后台备注，遇到非空 `evidence_filename` 直接拒绝；在安全上传链路完成前不创建 `evidence_media` 行。

## 2026-09-02 · 阶段 3 匿名投稿与图片治理边界

四种投稿共用一个严格的 Zod discriminated union（`new_place`、`new_price`、`correction`、`closure`），服务端拒绝未知字段、HTML、越界坐标和超价新地点。匿名接口以每日轮换盐和服务端密钥生成不可逆来源指纹，投稿/状态分别按小时限流；原始 IP 不落库。默认不信任客户端 `x-forwarded-for`，只有设置 `TRUST_PROXY=1` 且可信反向代理已剥离同名客户端头时才读取首个转发地址，公网部署前必须重新确定代理边界。新价格投稿可记录超过 ¥25 的涨价，但公开查询仍硬性隐藏超价餐食。

投稿成功只返回一次随机查询码和短期上传令牌，数据库只存哈希，查询码绝不兼作上传令牌。图片必须同时通过声明 MIME 与文件签名校验，服务端使用 Sharp 重新编码 WebP、去 EXIF、限制最长边 1600，并以服务端生成的相对路径保存；不保存用户原文件。默认 `admin_only`，权利确认和人工隐私检查完成、且证据关联正式价格事实后才允许公开。管理员上传的脱敏替代图通过 `replaces_media_id` 保留关联，原图继续保持私有。

四类 approved 写入（地点/餐食/价格、价格替换、白名单纠错、停业状态）与证据关联、投稿状态、审核记录和审计均在同一 SQLite 事务中；独立核验字段必填，商户自报不能直接成为公开事实。阶段 3 仅验证本地 SQLite/文件目录闭环，不代表公网生产就绪。
